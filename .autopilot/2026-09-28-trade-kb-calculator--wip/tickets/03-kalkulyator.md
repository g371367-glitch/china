## Что должно заработать

На странице «Калькулятор» вводишь товар: закупку в ¥, вес, габариты по желанию, категорию, тариф логистики и цену продажи в ¥ или ₽. Сразу видно рядом по четырём схемам (A — агент в Иу, B — поставщик сам, C — мини-запас, D — FBP): разбивка всех расходов на 1 заказ, прибыль, маржа и ROI в ¥ и ₽. Лучшая схема по прибыли выделена. Ниже поле «целевая маржа, %»: по нему для каждой схемы считается цена под эту маржу и цена безубыточности. Ещё на странице есть:
- курс CNY/RUB с кнопкой «обновить по ЦБ» и ручной правкой;
- «запас на конвертацию, %»;
- налоговый режим;
- галочка «без рекламы».

На странице «Тарифы» видны все цифры из `tariffs.default.json` с наложенными правками из `tariffs.json`. У каждой цифры источник, дата и отметка «исходная» или «моя». Цифры старше 90 дней помечены «пора перепроверить». Здесь можно править цифру, возвращать исходную и добавлять свою категорию. Неизвестная (null) цифра даёт пометку «расчёт неполный: нет данных по …», а не ноль.

Если к старту `data/tariffs.default.json` ещё нет или он неполный (таск 02 идёт параллельно), работай по схеме из спецификации. Тесты движка — на собственной фикстуре.

## Критерии приёмки

- [ ] `calc.js` — ES-модуль без DOM, экспортирует ровно сигнатуры из «Границ»; `node --test app/tests/` зелёный
- [ ] Тест: сумма строк разбивки = cost; profit = revenue − cost; margin = profit/revenue; ROI по формуле решения 9
- [ ] Тест: `priceForMargin` → подстановка в `computeUnit` даёт цель ±0,1 п.п. для всех 4 схем; недостижимая цель → `{unreachable, reason}` с суммой процентных удержаний
- [ ] Тест: расчётный вес = max(факт, объёмный) при заданных габаритах; ступени логистики выбираются правильно на границах
- [ ] Тест (D01): комиссия со ступенями `bands` по цене — выбирается правильная ступень на границах; одиночное `value` тоже работает; `unit: RUB` у денежных листьев переводится в ¥ по курсу
- [ ] Тест: реклама = max(%×цена, минимум₽/курс); «без рекламы» → 0
- [ ] Тест: налог — упрощёнка (0,04×0,05×выручка), обычный (5% от положительной прибыли, при убытке 0), свой %
- [ ] Тест: null-тариф → `incomplete` содержит ключ, NaN/Infinity нигде нет
- [ ] UI: неверный ввод подсвечивает поле с текстом по-русски, результат не показывает мусор; пересчёт на лету
- [ ] Переключатель ¥/₽ цены сохраняет значение через курс
- [ ] Курс: кнопка → `/api/rate` → сохранено в `settings.json` с датой; ошибка → «Нет связи с ЦБ, используется курс от ДАТА»; ручной ввод сохраняется
- [ ] Тарифы: правка пишет только изменённый лист в `tariffs.json` с `edited`; «вернуть исходную» удаляет правку; своя категория появляется в выпадающем списке калькулятора
- [ ] У каждой тарифной строки в разбивке видны источник и дата (иконка/подсказка)
