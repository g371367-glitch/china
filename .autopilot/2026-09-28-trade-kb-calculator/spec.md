# Спецификация: база знаний по торговле + калькулятор юнит-экономики Ozon Global / Иу

## Задача

У меня копятся заметки про компанию в Иу, Ozon Global, налоги Китая и России,
Южную Америку и торговый дом. Это россыпь .md-файлов, в которой местами стоит
«уточнить». Открывать их неудобно, общего поиска нет, а сроки отчётности приходится
выискивать в таблице. Ещё мне нужно быстро прикидывать, заработаю ли я на
конкретном товаре с 1688 при продаже через Ozon Global, и какая схема выгоднее:
чистый дропшиппинг через агента в Иу, отправка поставщиком, мини-запас или FBP.
Цифры тарифов при этом должны быть проверенными и с источником, чтобы им можно
было доверять.

## Решение

В папке проекта появляется ярлык «Запустить.bat». Двойной клик по нему открывает
в браузере локальный сайт:

- **Главная**: ближайшие сроки отчётности по Китаю и России (что горит в ближайшие
  30 дней, подсвечено), ниже разделы базы знаний и кнопка калькулятора.
- **База знаний**: все .md-заметки с меню по папкам и поиском по тексту. Новая
  заметка, положенная в любую папку, сразу появляется на сайте.
- **Калькулятор**: прибыль, маржа и ROI товара в ¥ и ₽; обратный расчёт цены под
  целевую маржу и цена безубыточности; сравнение четырёх схем бок о бок; сохранение
  товаров в список с выгрузкой в Excel (CSV).
- **Тарифы**: таблица всех цифр калькулятора с источником и датой проверки.
  Любую цифру можно заменить своей из кабинета Ozon и вернуть исходную.
- **Что изменилось**: журнал правок базы знаний в этом прогоне.

Сами заметки проверены по источникам. Устаревшее обновлено, пометки «уточнить»
закрыты там, где ответ есть в открытых источниках. Там, где ответ знает только
бухгалтер или агент, пометка осталась, и к ней добавлен готовый вопрос. Появилась
новая заметка с тарифами Ozon Global для категорий «дом и смежные».

Всё работает на этом компьютере без аккаунтов. Интернет нужен только для кнопки
«обновить курс по ЦБ».

## Решения по реализации

1. **Стек: Python 3 стандартной библиотеки + статические HTML/CSS/JS, без сборки и без npm.** Почему: Python у пользователя уже стоит (3.14), ставить ничего не нужно; нет зависимостей — нечему ломаться.
2. **Сервер `app/server.py` на `http.server`, слушает только 127.0.0.1.** Порт по умолчанию 8765; если занят нашим же сервером (GET /api/ping отвечает `{"app":"trade-kb"}`), просто открываем браузер; если занят чужим — берём следующий свободный. Почему: данные о компании не должны быть видны в сети.
3. **Markdown рендерится в браузере библиотекой marked, положенной в проект (`app/web/vendor/`).** Почему: офлайн, без CDN.
4. **Заметки — источник истины, читаются с диска при каждом запросе.** Папки знаний = все папки в корне, кроме служебных (`.autopilot`, `.git`, `app`, `data`, `.claude`, `node_modules`); корневые .md, кроме `CLAUDE.md`/`AGENTS.md`, тоже входят. Почему: новая заметка видна без команд.
5. **Поиск — на сервере, простым проходом по тексту без учёта регистра** (включая ё=е). Почему: 130 КБ текста ищутся мгновенно, индекс не нужен.
6. **Данные пользователя — JSON-файлы в `data/`**: `products.json`, `tariffs.json` (только правки пользователя), `settings.json` (курс, дата курса, запас на конвертацию, налоговый режим, дата регистрации компании, выбранная схема по умолчанию). Исходные тарифы — `data/tariffs.default.json`, календарь — `data/calendar.json`; оба пишутся исследованием, не пользователем. Запись атомарная (временный файл → replace). Почему: переживает очистку браузера и готово для будущего отчёта и модуля бухгалтера (R06, R08).
7. **Курс ЦБ — через сервер** (`/api/rate` ходит на `https://www.cbr-xml-daily.ru/daily_json.js`, берёт CNY Value/Nominal), таймаут 5 с. Почему: без ключей, без CORS-проблем; при ошибке — последний сохранённый.
8. **Движок расчёта — чистые функции в одном JS-модуле**, без DOM. Базовая валюта — ¥ (договор Ozon Global в CNY), рубли — через курс. Все деньги считаются в числах с плавающей точкой и округляются только при показе (¥ и ₽ до 2 знаков).
9. **Модель расходов на 1 заказ** (все ставки — из тарифов, с учётом правок):
   - закупка (¥), доставка по Китаю до точки отгрузки (¥), работа агента/склада (¥ за заказ), для C — доставка партии/хранение на единицу, для D — доставка до склада FBP + сборка/хранение на единицу;
   - международная логистика = f(расчётный вес, цена) по выбранному тарифу партнёра: `фикс ¥ + ставка ¥/г × вес`, опционально ступени по весу и цене; расчётный вес = max(факт, объёмный = Д×Ш×В/делитель), если габариты введены;
   - комиссия Ozon = % категории × цена (rFBS или FBP);
   - реклама «оплата за заказ» = max(% × цена, минимум ₽ / курс) — рублёвый минимум переводится в ¥ по текущему курсу (по умолчанию 5% и 5 ₽ из заметок); галочка «без рекламы» обнуляет строку;
   - эквайринг/конвертация = % × цена + пользовательский «запас на конвертацию» %;
   - резерв на возвраты/брак = % × цена (по схеме: B выше);
   - налог — по режиму (история 24);
   - прибыль = цена − Σ расходов; маржа = прибыль / цена; ROI = прибыль / (закупка + доставка по Китаю + работа агента/склада + логистика).
10. **Обратный расчёт — бисекция по цене** на [себестоимость, 100× себестоимость], потому что логистика и минимумы могут быть ступенчатыми; точность 0,01 ¥. Недостижимость определяется до поиска.
11. **Поля неизвестных тарифов — `null` + заглушка**, не ноль. Расчёт с `null` показывает итог с пометкой «неполный: нет данных по …». Почему: правило «не выдумывать» — выдуманная комиссия хуже пустой.
12. **Календарь** — `data/calendar.json`, события вида `{country, what, who, rule}`, где rule: `monthly(day)`, `quarterly([даты])`, `yearly(MM-DD)`, `once(дата)`, `afterRegistration(months)`. Главная разворачивает правила в ближайшие даты от сегодняшнего дня.
13. **Правки заметок** — прямо в .md, каждая изменённая цифра получает хвост `(проверено ДАТА, [источник](url))`; оставленные «уточнить» — с «Спросить бухгалтера: …» / «Спросить агента: …» / «Спросить поддержку Ozon: …». Старая версия — в git (исходный коммит a00d8f9).
14. **Интерфейс** — одностраничное приложение с хэш-маршрутами (`#/`, `#/doc/<путь>`, `#/search?q=`, `#/calc`, `#/tariffs`, `#/products`, `#/doc/Журнал_изменений.md`), русский язык, светлая и тёмная тема по системе, читается на ширине телефона. Подход «строго и без лишнего» (reference.md: образцов нет).
15. **Задел под R06–R08**: новые разделы добавляются как новый маршрут + новый JSON в `data/` через тот же `/api/data/<name>`; меню строится из списка маршрутов в одном месте.

16. **Целевой список категорий** (исследование сопоставляет их с реальными категориями Ozon и может объединить/переименовать по фактической сетке комиссий, записав это в заметку 05): Дом и сад; Посуда и кухня; Хранение и организация; Домашний текстиль; Хозтовары и уборка; Декор и праздники; Хобби и творчество; Канцелярия; Аксессуары (сумки, бижутерия, для волос); Игрушки (без батареек); Товары для животных; Спорт и отдых (мелочи); Автоаксессуары (мелочи).
17. **Логистика — целевой набор тарифов**: партнёры из заметок — OGL (официальная логистика Ozon), CEL, GBS, China Post; по каждому все публично доступные тарифы (эконом/стандарт/экспресс и т. п.) с формулой, ступенями, сроками. Что не нашлось публично — строка с `value: null` «нет данных — впишите из кабинета».
18. **Параметры схем** (в `schemes`, каждое — лист `{value, source, checked, note}`; значения по умолчанию — ориентиры из заметок 03, помеченные `note:"ориентир из заметок"`, пока исследование не найдёт лучше):
    - A (агент в Иу, rFBS): `cnDelivery` ¥/заказ (ориентир 0–5 → 3), `agentFee` ¥/заказ (1–5 → 3), `returnsReserve` доля (3–5% → 0,04), комиссия — rFBS.
    - B (поставщик сам, rFBS): `cnDelivery` (0), `supplierPackFee` ¥/заказ (→ 1), `returnsReserve` (→ 0,06 — выше из-за отсутствия контроля качества), комиссия — rFBS.
    - C (мини-запас у агента, rFBS): `batchDiscount` доля скидки к закупке при партии (→ 0), `inboundPerUnit` ¥ (→ 1), `storagePerUnit` ¥ (→ 0,5), `agentFee` (→ 2), `returnsReserve` (→ 0,03), комиссия — rFBS.
    - D (FBP): `batchDiscount` (→ 0), `inboundPerUnit` ¥ до склада партнёра (→ 1), `fbpHandling` ¥/заказ (сборка/хранение; `null` если не найдено), `returnsReserve` (→ 0,03), комиссия — FBP (если нет данных — rFBS − 1 п.п. с пометкой «оценка по заметкам»).
19. **Допустимые источники для правок заметок**, по убыванию веса: официальные ресурсы Ozon (seller-edu.ozon.ru, docs.ozon.ru, seller.ozon.ru, global.ozon.ru и их китайские версии), официальные госресурсы (nalog.gov.ru, consultant.ru/garant.ru — тексты актов, chinatax.gov.cn, gov.cn, cbr.ru, customs.gov.ru); затем отраслевые СМИ и крупные профильные издания с пометкой «по данным сторонних источников». Форумы, блоги, видео — только как подсказка, куда смотреть, не как источник цифры. Если официальный и сторонний расходятся — вписывается официальный, расхождение упоминается.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|

Схема тарифов (контракт между таском исследования и калькулятором):

```json
{
  "version": 1, "checked": "2026-09-28",
  "categories": [{"id":"home","name":"Дом и сад","rfbs":{"value":0.12,"source":"url","checked":"2026-09-28"},"fbp":{"value":null,"source":null,"checked":null,"note":"нет данных — впишите из кабинета"}}],
  "logistics": [{"id":"ogl-standard","name":"OGL Стандарт","fixed":{"value":…},"perGram":{"value":…},"bands":[{"maxWeight":…,"maxPrice":…,"fixed":…,"perGram":…}],"days":"10–15","source":…,"checked":…}],
  "fees": {"acquiring":{…}, "adsPerOrder":{…}, "adsMinRub":{…}, "returnsReserve":{…}, "volumetricDivisor":{…}, "dutyFreeLimit":{…}},
  "schemes": {"A":{"cnDelivery":{…},"agentFee":{…},"returnsReserve":{…}}, "B":{"cnDelivery","supplierPackFee","returnsReserve"}, "C":{"batchDiscount","inboundPerUnit","storagePerUnit","agentFee","returnsReserve"}, "D":{"batchDiscount","inboundPerUnit","fbpHandling","returnsReserve"}},   // поля — по решению 18
  "tax": {"simplified":{"base":0.04,"rate":0.05}, "regular":{"rate":0.05}}
}
```

Каждое число-листа — объект `{value, source, checked, note?, unit?}`; `unit` ∈ `CNY` (по умолчанию для денег), `RUB`, `EUR`, `share` (доля 0–1), `g`, `cm3/kg`. **Поправка D01 (таск 02, 2026-09-28):** с 01.12.2025 комиссия Ozon зависит от ценовой ступени товара, поэтому лист комиссии категории (`rfbs`/`fbp`) может вместо одного `value` нести `bands: [{maxPrice, value}]` (maxPrice в `unit` листа, последний `maxPrice: null` = без верхней границы); `computeUnit` выбирает ступень по цене продажи. Беспошлинный лимит хранится в EUR: калькулятор показывает предупреждение «цена выше беспошлинного лимита», только если известен курс EUR, иначе это справочная строка без проверки. Категории несут поле `ozonCategory` (строка). `value: null` = нет данных. `data/tariffs.json` (правки) — та же форма, только изменённые листья, плюс `"edited": "дата"`; `mergeTariffs` накладывает правки на исходные.

**Швы для тестов:** `calc` и `calendar` (чистые функции, тесты на `node --test`), `server` HTTP API (тесты на `python -m unittest`, поднимают сервер на свободном порту с временным корнем). UI проверяется прогоном в браузере на финальной приёмке.
