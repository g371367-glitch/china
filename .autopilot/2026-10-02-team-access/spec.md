# Спецификация: доступ к сайту для коллег

## Задача

Сайт базы знаний (заметки, калькулятор, список товаров, тарифы) работает только на моём компьютере.
Я хочу, чтобы коллеги — они в Китае и ходят в интернет через VPN — открывали его по ссылке из любого места,
работали с теми же товарами, тарифами и настройками, что и я, и чтобы посторонние туда не попали.
Платить за хостинг я не хочу: пусть сайт остаётся у меня и работает, пока включён компьютер.

## Решение

- Рядом с «Запустить.bat» появляется **«Доступ для коллег.bat»**. Двойной клик — и:
  - при первом запуске он просит придумать пароль (дважды) и запоминает его;
  - если на компьютере нет программы-туннеля cloudflared, предлагает скачать её с официальной страницы Cloudflare (с вопросом «да/нет»);
  - поднимает сайт и бесплатный туннель Cloudflare, печатает **ссылку для коллег** вида `https://…trycloudflare.com` и кладёт её в буфер обмена;
  - пока окно открыто, коллеги работают; закрыл окно — доступ закрыт.
- Коллега открывает ссылку → видит страницу входа → вводит общий пароль → попадает на тот же сайт. Без пароля не открывается ничего: ни заметки, ни калькулятор, ни данные.
- Данные общие: товар, сохранённый коллегой, сразу виден мне и остальным (после открытия экрана заново). Если двое правят одновременно, правки не затирают друг друга: каждая запись сохраняется поверх свежей версии.
- **«Сменить пароль.bat»** — новый пароль; все, кто вошёл со старым, выходят и должны ввести новый.
- У себя я по-прежнему запускаю «Запустить.bat» и пользуюсь сайтом без пароля, как раньше. Когда доступ для коллег включён, на главной у меня видна текущая ссылка с кнопкой «Копировать».
- Заметка «Доступ для коллег» в базе знаний объясняет всё по шагам.

## Решения по реализации

1. **Два сервера в одном процессе.** Режим «для коллег» — второй экземпляр того же HTTP-сервера на другом порту (8766 и выше), тоже на 127.0.0.1, с включённой проверкой пароля. Туннель смотрит только на него. Почему: туннель приходит на сервер с адреса 127.0.0.1, по адресу «свой/чужой» не различить; отдельный порт — единственная надёжная граница, и локальный режим (8765) остаётся нетронутым.
2. **Туннель — быстрый туннель Cloudflare**: `cloudflared tunnel --no-autoupdate --url http://127.0.0.1:<порт>`, ссылка вылавливается из вывода (`https://<что-то>.trycloudflare.com`). Почему: бесплатно и без аккаунта (ответ пользователя); у коллег VPN. Программа ищется: `tools/cloudflared.exe`, затем PATH. Скачивание — только с согласия, с `https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe` во временный файл → переименование в `tools/cloudflared.exe`. `tools/` — в `.gitignore`.
3. **Пароль** хранится в `data/access.json`: `{"version":1, "salt", "hash", "iterations", "epoch", "secret", "changedAt"}` — PBKDF2-HMAC-SHA256, 200 000 итераций, соль 16 байт; `secret` — 32 случайных байта для подписи входов. Файл **не** входит в DATA_READ/DATA_WRITE — через API его не прочитать и не записать. Смена пароля меняет `secret`, поэтому все выданные входы недействительны. Пароль в чат, логи и файлы открытым текстом не попадает. Почему PBKDF2: есть в стандартной библиотеке.
4. **Вход** — cookie `kb_session` = `<выдан, unix-время>.<HMAC-SHA256(secret, выдан)>` в base64url; `HttpOnly`, `SameSite=Lax`, `Path=/`, `Max-Age` 30 дней; `Secure`, если запрос пришёл по https (заголовок `X-Forwarded-Proto: https` или `Cf-Visitor` с `https`). Проверка: подпись верна и выдан не раньше 30 дней назад. Секрет читается из `access.json` при каждой проверке (или кэш с проверкой mtime), поэтому смена пароля из другого процесса действует сразу.
5. **Защита от перебора** — в памяти процесса: по адресу клиента (`Cf-Connecting-IP`, иначе адрес соединения) 5 неудач → блок 15 мин; глобально 30 неудач за скользящие 15 мин → блок всех на 15 мин. Успешный вход сбрасывает счётчик адреса. Почему глобальный предел: адрес из заголовка можно подделать.
6. **Что открыто без входа** на сервере для коллег: `GET /login` (страница входа), `GET /css/style.css`, `POST /api/login`, `POST /api/logout`. Всё прочее без входа: `GET` не-API → `303` на `/login`; `/api/*` → `401 {"error":"Нужно войти"}`. Клиент на 401 переходит на `/login`.
7. **Конфликты** — версия файла данных. `GET /api/data/<name>` отдаёт заголовок `ETag: "<sha256 содержимого файла, 16 hex>"` (для отсутствующего файла — `"none"`). `PUT` с заголовком `If-Match`: версия не совпала → `409 {"error":"Данные изменились — обновите"}`; совпала → запись. `PUT` без `If-Match` пишет как раньше. Проверка версии и запись — под **межпроцессным** замком на имя файла: файл-замок `data/.<name>.lock`, захват `msvcrt.locking` (Windows) / `fcntl.flock` (прочие), ожидание до 5 с, затем `503 {"error":"Данные заняты — попробуйте ещё раз"}`. Межпроцессный — потому что обычный сайт («Запустить.bat») и сайт для коллег могут работать в двух разных процессах (история 20) и писать одни и те же файлы.
8. **Клиент пишет только «правкой поверх свежего»**: `api.update(name, fn)` читает данные с версией, вызывает `fn(текущее)` → новое, пишет с `If-Match`; на 409 повторяет (до 3 попыток), затем `ApiError` со status 409 и текстом из истории 18. Все четыре места записи переводятся на него и выражают изменение как операцию над текущими данными: товар — upsert/удаление по `id`; настройки — слияние патча (`saveSettingsPatch`); тарифы — установка/сброс листа по пути, добавление своей категории. Экран после успешной записи берёт возвращённое значение (так он видит и чужие правки). `api.saveData` остаётся для совместимости, экраны его больше не вызывают.
9. **Режим сайта для клиента**: `GET /api/ping` → `{app, version, team}` — `team:true` на сервере для коллег (для пункта «Выйти»). `GET /api/team` на локальном сервере → `{active:true, url}` или `{active:false}`; на сервере для коллег — 404.
10. **Запуск**: `app/team.py` — точка входа режима для коллег; `--set-password` — только сменить пароль и выйти. «Доступ для коллег.bat» и «Сменить пароль.bat» — CRLF, UTF-8, ищут Python так же, как «Запустить.bat». Ctrl+C или закрытие окна гасит cloudflared (дочерний процесс; на Windows — job-объект не нужен: `atexit` + обработчик закрытия консоли `SetConsoleCtrlHandler` через ctypes, при невозможности — хотя бы `atexit`).
11. **Подписи по-русски, без трассировок** во всех сообщениях окна; неожиданная ошибка → одна строка «Ошибка: …» и ожидание клавиши (это делает bat через `pause`).

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `app/server.py` (данные) | файлы `data/*.json` | `read_data(root, name) → value \| None` (как было); `read_data_versioned(root, name) → (value, etag)`; `write_data(root, name, value, if_match=None)` — бросает `DataConflict` при несовпадении; `etag_of(root, name) → str` | межпроцессный замок записи (`data/.<name>.lock`), формат ETag |
| `app/server.py` (HTTP) | маршруты, режимы | `make_server(root, host, port, rate_url, access=None, team_info=None)` — `access` задан → сервер для коллег с паролем; `team_info` — объект с атрибутом `url` (или `None`) для `/api/team` на локальном | проверку cookie, перенаправления |
| `app/auth.py` (новый) | пароль, входы, перебор | `class Access(root)`: `configured() → bool`, `set_password(pw)`, `check_password(pw) → bool`, `issue() → token`, `verify(token) → bool`; `class LoginLimiter(clock=time.monotonic)`: `check(ip) → (ok, retry_after_s)`, `failure(ip)`, `success(ip)`; `MIN_PASSWORD = 8`, `SESSION_DAYS = 30` | формат `access.json`, PBKDF2, HMAC |
| `app/team.py` (новый) | запуск для коллег, туннель | `find_cloudflared(root) → path \| None`; `download_cloudflared(root, progress) → path`; `class Tunnel(exe, port)`: `start(timeout=40) → url`, `alive() → bool`, `stop()`; `parse_tunnel_url(line) → str \| None`; `main(argv)` | разбор вывода cloudflared, ввод пароля, буфер обмена |
| `app/web/js/api.js` | HTTP-клиент | добавляется `api.update(name, fn, {retries:3}) → Promise<новое значение>`; `api.logout()`; `api.team()`; на 401 любого запроса — переход на `/login` | ETag, повторы |
| `app/web/login.html` (новый) | страница входа | — | — |

**Швы для тестов:** `app/auth.py` (`Access`, `LoginLimiter` — напрямую, с подставными часами); HTTP через `make_server` на временном корне (как в `test_server.py`): 401/303/вход/выход/ETag/409; `parse_tunnel_url` — на строках вывода cloudflared; `api.update` — в node с подменённым `globalThis.fetch`. Реальный cloudflared в тестах не запускается.
