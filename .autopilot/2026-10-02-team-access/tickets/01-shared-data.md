## Что должно заработать

Несколько человек работают с одними данными (товары, тарифы, настройки). Когда двое сохраняют
разные записи одновременно, сохраняются обе; когда один удалил товар, а другой в это же время добавил
свой, — удалённого нет, добавленный есть. Одну и ту же запись побеждает последнее сохранение, прочие
записи не трогаются. После трёх конфликтов подряд пользователь видит понятную ошибку, а введённое на
экране не теряется. Работает и тогда, когда пишут два разных процесса сервера.

## Из брифа, дословно

> «Общие на всех» — «Один общий список товаров и тарифов: что вписал один, видят все.»

## Критерии приёмки

- [ ] `GET /api/data/<name>` отдаёт `ETag` (sha256 содержимого, 16 hex, в кавычках; нет файла → `"none"`)
- [ ] `PUT` с `If-Match`: совпало → запись и `{ok:true}`; не совпало → `409 {"error":"Данные изменились — обновите"}`; без `If-Match` — как раньше
- [ ] Проверка версии и запись — под межпроцессным замком `data/.<name>.lock` (`msvcrt.locking` / `fcntl.flock`), ожидание до 5 с → `503 {"error":"Данные заняты — попробуйте ещё раз"}`; `data/.*.lock` в `.gitignore`
- [ ] `read_data_versioned`, `write_data(..., if_match=None)` с `DataConflict`, `etag_of` — как в «Границах»; `read_data` прежний
- [ ] `api.update(name, fn, {retries:3})` — чтение с версией, `fn(текущее)`, запись с `If-Match`, повтор на 409; исчерпано → `ApiError` 409 «Данные одновременно меняет кто-то ещё — попробуйте ещё раз»
- [ ] Все места записи (сохранение товара в калькуляторе, удаление товара, правка/сброс тарифа и своя категория, `saveSettingsPatch`) выражены операцией над свежими данными через `api.update`; экран после записи показывает возвращённое значение
- [ ] Тесты: Python — ETag, 409, запись без If-Match, замок (второй поток ждёт); node — `api.update` с подменённым `fetch` (успех, повтор после 409, исчерпание), операции товаров/тарифов поверх чужих изменений
- [ ] Все прежние тесты зелёные
