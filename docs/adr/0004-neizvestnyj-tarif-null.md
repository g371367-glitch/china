# 0004. Неизвестный тариф — `null` и неполный расчёт, а не ноль и не оценка

## Контекст

Часть тарифов Ozon Global, партнёров логистики и склада FBP в открытых источниках не найти. А цифрам калькулятора нужен источник, иначе им нельзя доверять.

## Решение

Цифра, которой нет в открытых источниках, хранится как `value: null` с пометкой «нет данных — впишите из кабинета». Расчёт с такой цифрой показывает итог с пометкой «неполный: нет данных по …». Ориентиры из заметок (ставки агента и т. п.) допускаются только с явной пометкой «ориентир из заметок».

## Почему

- **Ноль вместо пустоты** — незаметно завышает прибыль: товар выглядит выгодным, потому что расход забыт. Это хуже пустого поля.
- **Средняя оценка по рынку или форумам** — нарушает правило «не выдумывать»: выдуманная комиссия без источника неотличима от проверенной.
- **Не считать, пока всё не заполнено** — калькулятор не работал бы с первого дня: по FBP и части логистики данных нет совсем.

## Последствия

- Пока владелец не впишет цифры из кабинета, часть расчётов будет помечена неполной. Сравнение схем с неполной колонкой нужно читать осторожно.
- Лучшая схема может быть выделена по неполному расчёту, и единственная защита здесь — пометка.
- Исключение, о котором надо помнить: если данных по комиссии FBP нет, берётся rFBS − 1 п.п. с пометкой «оценка по заметкам». Это оценка, а не `null`.
